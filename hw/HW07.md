## Logistic Regression

You will implement the logistic regression task discussed in class for
**binary classification**. Implement the model yourself using NumPy for
arithmetic; do not use a library classifier for this part.

### Model

Assume the features are continuous and the response is a discrete, binary
output. In the case of binary labels, the probability of a positive prediction is:

$$h_{\vec{w}}(\vec{x})=p(y=1\mid\vec{x})=\frac{1}{1+e^{-\vec{w}\cdot\vec{x}}}$$

To model the intercept, include a bias term: a feature that is always “on”.
For this starter, **prepend** a 1 to each feature vector using `add_ones()`.
The first weight is the learned intercept. Training and prediction receive
raw features and add the bias exactly once; `logistic()` receives an already
augmented feature vector.

Implement `logistic()` using the dot product. For numerical stability, if
`z = x dot w` is nonnegative, use `1/(1+exp(-z))`; otherwise use
`exp(z)/(1+exp(z))`. This avoids overflow for large positive or negative scores.

### Training

To learn the weights, apply stochastic gradient descent (SGD) until the cost
function changes very little between iterations. Our cost is the **negative
log** of the likelihood function, where the likelihood is:

$$L(\vec{w})=\prod_{i=1}^{n}h_{\vec{w}}(\vec{x}_i)^{y_i}(1-h_{\vec{w}}(\vec{x}_i))^{1-y_i}$$

Implement `costJ()` as the **sum** of negative log likelihoods, using natural logs:

$$J(\vec{w})=-\sum_{i=1}^{n}\left[y_i\log(p_i)+(1-y_i)\log(1-p_i)\right]$$

Clip probabilities to `[1e-15, 1-1e-15]` before computing the logarithms.
Use this same cost for stopping. No regularization is required.

Use the same idea as in HW03 for linear regression:

```text
initialize weights to zeros
while not converged:
    shuffle the training examples
    for each training example xi:
        calculate the derivative of the cost
        weights = weights - alpha * derivative
    compute the current cost
```

The SGD updates are:

$$\vec{w}\leftarrow\vec{w}-\alpha\left(h_{\vec{w}}(\vec{x}_i)-y_i\right)\vec{x}_i$$

The hyperparameter `alpha` is passed to SGD and used in training. A few notes:

- Shuffle the data points on every epoch, making sure y is shuffled along
  with X. Use **one** `np.random.default_rng(seed)` generator created before
  the loop, and iterate through `rng.permutation(n)` each epoch. Using the
  same index for X and y preserves their pairing.
- An epoch visits all training examples. Stop after `tmax` epochs, or when
  the absolute change in cost between two completed epochs is strictly less
  than `eps`. Compare costs starting with the second epoch. Always complete
  the first epoch; `eps=0` disables early stopping.
- Defaults are `eps=1e-4`, `tmax=1000`, and `seed=0`. You can change these
  with `--eps`, `--tmax`, and `--seed` when running the driver.
- Return a one-dimensional array of weights with the bias first. Do not
  modify input arrays or pause for user input. Reject nonfinite/nonpositive
  alpha, nonfinite/negative eps, tmax below 1, and empty training data with
  `ValueError`, as described in the starter docstrings.
- Many operations are on vectors. NumPy dot products can make them simpler.

Choose hyperparameters using training-only validation, then report test
performance. Avoid choosing parameters by repeatedly evaluating the test set.
